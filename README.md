# ATシミュレーター

`index.html` をブラウザで開いて、試行条件を入力し「実行」を押します。GitHub Pages では、配信元をこの3ファイルがあるブランチのルートに設定します。ビルドや依存パッケージは不要です。

## 試行条件と集計

- 試行回数は100〜100,000回です。同じ整数シードと試行条件で同じ結果を再現できます。
- ランダム開始時は、平均−1,000・標準偏差1,000の正規分布から−5,000〜999枚に収まる値を引いて整数に丸めます。固定値も指定できます。
- テーブル閾値の倍率は全テーブルに一律で適用します。初期値は1倍、強いVストックは10%、特化のストック率は50%、加速はOFFです。
- 獲得差枚とヒストグラムはAT中の差枚を集計します。CZ内訳はテーブル・レア役それぞれの総発生回数を総セット数で割った値です。各発動率は該当イベントが1回以上起きた試行の割合です。引き戻し率はプールからの復帰を数えます。
- 「切断発動率」はエンディングなどを含む全区間切断の発生率です。「切断ストック発動率」は切断条件付きのストックを消化開始した試行の割合です。

## エンジン

初回は純増3枚モードの100G、以後は50G単位で強いストックから優先して消化します。純増3枚モードのベルナビ率は61.9%、純増6枚モードは全ナビです。テーブルはプラス差枚のゲームだけを加算し、到達時にテーブル移行を抽選します。CZはエンディング突入を除き3G消化し、特化の報酬はストックか加算ゲーム数を抽選します。

エンディングは区間差枚が+2,200枚を超えると始まり、+2,400枚以上まで最終ゲームの超過分を含めて払い出します。区間切断からの再開は純増3枚モードの50Gと弱いストック2個で始まります。フリーズ、32Gの引き戻し、切断ストック、加速の抽選と処理順は `reference/at.py` に準拠します。Node APIでは `simulate({ maxSets: 数値 })` でセット上限も指定できます。

```sh
node sim.js
```

CPythonの整数シード初期化、MT19937、試行ごとの64ビットシードを再現しています。Python版を実行して比較した結果、対応する全10,000試行のAT差枚が一致しました。タスク記載の丸め値（+2,572.9枚）に対する平均の相対差は約+0.000284%です。

